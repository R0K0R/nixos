# qtbase: `stdlib.h: No such file or directory` in cross build (GCC + CMake)

**Package:** `qtbase-x86_64-unknown-linux-gnu-6.11.0`
**File:** `pkgs/development/libraries/qt-6/modules/qtbase/default.nix`

## Symptom

```
/nix/store/...-x86_64-unknown-linux-gnu-gcc-15.2.0/include/c++/15.2.0/cstdlib:83:15: fatal error: stdlib.h: No such file or directory
   83 | #include_next <stdlib.h>
      |               ^~~~~~~~~~
compilation terminated.
```

Fails in many qtbase source files (e.g., `removed_api.cpp`, `qsocketnotifier.cpp`).

## Root Cause

### The Include Search Path Problem

The Nix cross GCC cc-wrapper correctly adds glibc's include path with `-idirafter`:
```
g++ ... -idirafter /nix/store/glibc-dev/include -idirafter .../include-fixed ...
```

Without explicit `-isystem` flags, the GCC search path is:
```
1. .../c++/15.2.0/          ← C++ standard headers (cstdlib is here)
2. .../c++/15.2.0/x86_64-unknown-linux-gnu/
3. .../c++/15.2.0/backward/
4. .../lib/gcc/.../include
5. .../include
6. .../include-fixed         ← empty for cross GCC (only README)
7. glibc.../include          ← from -idirafter (glibc's stdlib.h is HERE)
```

`#include_next <stdlib.h>` from cstdlib (at pos 1) searches pos 2+, finds stdlib.h at pos 7. ✓

### CMake Breaks the Order

CMake detects compiler system includes by running the cross compiler with `-v`.
CMake then re-emits the glibc include path as an **explicit `-isystem`** flag in
all generated compile commands (from Qt6 cmake target propagation or cmake's
implicit include detection). This moves glibc to position 1:

```
1. glibc.../include          ← from explicit -isystem (MOVED TO FRONT)
2. glib.../include           ← from explicit -isystem
3. .../c++/15.2.0/           ← C++ standard headers (cstdlib is HERE)
...
8. .../include-fixed          ← empty
```

Now `#include_next <stdlib.h>` from cstdlib (at pos 3) searches pos 4+. No stdlib.h
anywhere (include-fixed is empty, glibc is at pos 1 which is BEFORE cstdlib). ✗

### Why Cross GCC's `include-fixed` is Empty

Native GCC's `include-fixed/stdlib.h` is generated by `fixincl` running against
the native sysroot during GCC's own build. Cross GCC builds without a sysroot,
so fixincl produces nothing → `include-fixed/` only contains README.

## Fix

Add the C++ headers directory as an explicit `-I` flag. Since `-I` directories
appear BEFORE `-isystem` directories in GCC's search path, this ensures:
```
1. .../c++/15.2.0/           ← from explicit -I (cstdlib found HERE)
2. glibc.../include          ← from CMake's explicit -isystem
...
```

`#include_next <stdlib.h>` from cstdlib (pos 1) → searches pos 2 → finds stdlib.h. ✓

In `qtbase/default.nix`:
```nix
env.NIX_CFLAGS_COMPILE =
    "-DNIXPKGS_QT_PLUGIN_PREFIX=\"${qtPluginPrefix}\""
    + lib.optionalString isCrossBuild
      " -I${stdenv.cc.cc}/include/c++/${lib.getVersion stdenv.cc.cc}";
```

`isCrossBuild = !stdenv.buildPlatform.canExecute stdenv.hostPlatform` (already defined in the let block).

**Status: FIXED**
